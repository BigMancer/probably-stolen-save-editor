# 深空当铺 — 存档修改器

[English](README.md) · **简体中文**

**Probably Stolen**（中文名：深空当铺）的存档修改器 —— 单文件、完全离线。浏览器打开页面，把 `.es3`
存档拖进去，改完导出覆盖原存档即可。

不用安装、不用构建、不用起服务、不联网，全部逻辑都在页面里跑。

```
存档修改器.html      ← 整个修改器（双击打开）
```

> 游戏存档属于个人数据，**不入库**（见 `.gitignore`）。

---

## 功能

**常用数值** —— 现金、荒野声望、天数、收租/还贷倒计时、各种加价率、店铺指标（秩序、客流、幸福度、
水质纯度）、势力数值、健康状态、客户与检查倒计时、游玩时长。一页带中文标签的输入框。

**🧩 库存** —— 解析内嵌的库存 JSON（`mainInvJSON` / `soldInvJSON`）：

| | |
|---|---|
| 列表 | 物品名、`identifier`、🏷 自定义名（`CUSTOM_NAME_TAG`）、数量/单价/基础价、所在容器、类型标签 |
| **`_values` 属性编辑器** | 按物品列出它的 `_keys`，每行显示中文名 + 原始 tag + **一个可直接编辑的输入框**。改哪个字段按 tag 后缀自动挑：`*_INT → valueInt`、`*_FLOAT → valueFloat`、`*_LONG → valueLong`、`*_BOOL → valueBool`，其余优先取非空的 `internalValueString`（自定义名、锁 ID、制造方…）；纯标记型 tag（`IS_OWNED_TAG` 等）给一个启用/关闭开关。点 `▸` 展开该项的全部 9 个字段 |
| 过滤 | 按物品名 / identifier / 自定义名 / 类型（`MODULE`、`STORAGE`、🏷 …） |
| 分组 | 按类型 / 归属容器 / 物品名 / identifier，分组后默认**全部收起**，有「全部收起 / 全部展开」 |
| 批量 | 勾选行（或用「选中本组」/ 表头全选），然后在任意一件选中物品上改属性 —— 同一个 tag 的同一个字段会写到其余所有选中项；类型不一致的自动跳过，不会写坏。关掉「批量同步」开关就只改当前一件 |

**全部字段** —— 整份存档的懒加载树（参考存档 8,122 个字段）。值本身是 JSON 的字符串字段（`mainInvJSON`
等）会展成子结构，所以搜索能进到库存**内部**：搜 `弹药` 会命中
`playerStore.mainInvJSON ▸ saveItems[43].name`。搜索结果是可以直接改的扁平行。

**改动清单** —— 列出全部待导出的改动（原值 → 新值），支持逐项撤销和整体还原。

**自动恢复** —— 已加载的存档 + 尚未导出的改动缓存在 IndexedDB 里；关掉页面再打开就回到上次的现场
（「忘记上次」可清除缓存）。

深色/浅色主题自适应，界面中文。

## 使用

1. 双击 `存档修改器.html`（任意 Chromium 内核浏览器，实测 Edge / Chrome）。
2. 点「选择存档」或把 `.es3` 拖进页面。
3. 随便改。
4. 点「导出修改后的存档」→ 会下载一个同名文件 → 用它覆盖原存档。

默认存档位置（Windows）：

```
%USERPROFILE%\AppData\LocalLow\Questing Goose Studio\Probably Stolen\save_1.es3
```

（同目录还有 `save_0.es3`、`SaveFile.es3`、`saves_index.es3`。）

**覆盖前先备份存档，并且替换时游戏要关掉。**

## 写回机制（为什么不会改坏）

`.es3` **不是**标准 JSON。参考存档里的实际情况：

* 60 处字典键是没引号的数字 —— `{...,8376:{...},-103:{...},...}`
* 20 处非法转义 —— `\“` / `\”`
* 整个库存是**JSON 里套 JSON 字符串**（`mainInvJSON`，119 万字符，287 件物品）
* 游戏新版本会把文件写成带缩进 + CRLF 换行的形式

所以修改器的做法是：

1. 用自带的宽容解析器解析（支持裸数字键、非法转义、尾逗号），并记录每个值的**字符偏移**；
2. 导出时**只替换你实际改动过的值所占的字符区间**，其余内容（包括原文的 `\/` 转义、缩进、换行）
   逐字节原样保留；
3. 改动落在内嵌 JSON 字符串里时，用「转义感知」的方式局部改写外层字符串字面量，119 万字符里其余部分
   一个字节都不动；
4. 下载前重新解析导出结果，按路径逐项回读比对，状态栏显示
   `✔ 外层校验通过 / ✔ 内嵌 JSON 校验通过`，有问题会点名是哪一项。

在参考存档上实测：不改任何值的导出与输入文件**逐字节相同**；改动库存里的值后，只有目标字符发生变化，
其余 285 件物品逐字节不变。

## 测试

开发期用 Node + jsdom 验证界面行为，用真实无头 Edge（`puppeteer-core`）验证布局与几何。脚本放在仓库
外的临时目录，覆盖：

* 宽容解析器：统计信息、无改动往返一致、改动路径回读
* 界面：库存渲染、内嵌 JSON 内搜索、分组收起/展开、选中 + 批量同步
* 持久化：改值 → 刷新页面 → 存档与改动都恢复
* 布局：表头与数据行的列几何（`getBoundingClientRect`）完全一致
